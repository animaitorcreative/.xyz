The current philosophy

Animaitor is based on a pretty simple idea:

AI should understand the project, not just the prompt.

Most AI creative tools are very good at doing one thing:

You ask for something.

They make something.

Then you ask for something else.

They make something else.

Then three generations later you're wondering why your main character has changed ethnicity, clothing, species, hairstyle, age, and possibly tax status.

Animaitor is intended to maintain project context.

A project can contain:

PROJECT
│
├── World
├── Characters
├── Locations
├── Assets
├── Stories
├── Episodes
├── Scenes
├── Style
├── Voice
├── Music
├── Animation
├── Continuity
├── Versions
└── Production History

The more the platform understands the project, the more useful the AI can become.

The basic workflow

Eventually, using Animaitor should feel something like this:

1. Create a project
        ↓
2. Tell Animaitor what you're making
        ↓
3. Build the project's context
        ↓
4. Start creating
        ↓
5. Review what happened
        ↓
6. Fix what needs fixing
        ↓
7. Produce the good stuff
        ↓
8. Learn from the process
        ↓
9. Make the next thing better

That's the basic loop.

We don't expect creative work to happen in a perfectly straight line.

Because creative work doesn't.

Neither does software development.

Neither does life.

So we're not going to make Animaitor pretend otherwise.

Start with something real

The best way to learn Animaitor is not to read this README twelve times.

It's to make something.

Projects have memory

One of the major ideas behind Animaitor is project memory.

If you establish something important, the system should eventually be able to remember it.

For example:

"This is what the character looks like."

Then later:

"Make another scene with this character."

Animaitor shouldn't respond:

"Absolutely. Here's a completely different person."

That's not creativity.

That's amnesia with a GPU.

The project should maintain important information such as:

approved character designs
locations
styles
story facts
continuity
assets
decisions
versions
references

Review

AI-generated content is not automatically good.

Shocking, I know.

Review the result.

Ask:

Does this fit the project?
Is the character correct?
Does the style match?
Does the story make sense?
Is the continuity correct?
Is this actually useful?
Should we keep it?
Should we try again?

The human remains the creative authority.

AI is the assistant.

A very fast assistant.

Occasionally an extremely confident assistant.

But still the assistant.

Refine

Good production is iterative.

You make something.

You look at it.

You improve it.

You make another version.

You improve that.

Eventually you stop saying:

"Okay, this is garbage."

and start saying:

"Okay, we're getting somewhere."

Animaitor should preserve useful context throughout that process.

Local-first

Animaitor is being developed with a local-first philosophy.

That means local AI and local tools should be first-class citizens.

But:

Local-first does not mean local-only.

Sometimes the best tool for a job will be local.

Sometimes it won't.

We want Animaitor to be able to work with different models, providers, services, and tools.

Ideally, the user shouldn't have to care about the plumbing every time.

You should be able to say:

"Make this."

and Animaitor should worry about:

"Which combination of tools is actually appropriate for this?"

Development philosophy

Animaitor is being developed according to a pretty straightforward loop:

BUILD
  ↓
USE
  ↓
BREAK
  ↓
FIX
  ↓
USE AGAIN
  ↓
NOTICE A PATTERN
  ↓
ABSTRACT IT
  ↓
MAKE IT REUSABLE
  ↓
PUT IT IN THE PLATFORM

This is preferable to spending two years designing the world's most sophisticated button before discovering nobody wants the button.

The rules
Rule #1

Make something real.

Rule #2

Don't build infrastructure just because infrastructure is fun.

Rule #3

If infrastructure is fun, at least make it useful afterward.

Rule #4

Document what we learn.

Rule #5

Don't let the AI convince us that a bug is a feature.

Rule #6

If the AI gives a character three arms, we investigate.

If it gives the character three arms and the story somehow becomes better, we reconsider Rule #5.
